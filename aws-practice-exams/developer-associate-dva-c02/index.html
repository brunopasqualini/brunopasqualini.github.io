Sample question 1 Development with AWS Services

A Lambda function is subscribed to a standard SQS queue with a batch size of 10. Occasionally one message in a batch has a malformed payload and the function throws an exception. The whole batch then returns to the queue and the nine healthy messages are processed again, causing duplicate side effects. The team must keep batching for throughput but wants only the failing message retried. What should the developer do?

  1. Increase the queue's visibility timeout so that healthy messages are not returned when the function fails
  2. Enable ReportBatchItemFailures on the event source mapping and return the failed message IDs in a batchItemFailures response
  3. Set maxReceiveCount to 1 in the queue's redrive policy so that only the failing message is moved aside
  4. Catch the exception in the handler and return normally so that Lambda deletes the batch, then log the failing message body
Show the answer and explanation

Correct answer: B.

Option A is incorrect because a failed invocation still leaves all ten messages in flight and they all reappear after the timeout; the timeout does not select individual messages. Option B is correct because the function tells Lambda exactly which messages failed, so Lambda deletes the successful ones and only the failed ones become visible again, while batching is preserved. Option C is incorrect because receive counts are incremented for every message in the failed batch, so the healthy messages are moved to the dead-letter queue as well. Option D is incorrect because a normal return makes Lambda delete every message in the batch, so the failing message is lost instead of retried. With SQS event source mappings, an exception fails the entire batch unless the function opts in to partial batch responses.

Sample question 2 Security

A Lambda function needs to read objects from an S3 bucket in the same account. Which approach follows AWS best practice for granting this access?

  1. Attach an execution role to the function with an IAM policy that allows s3:GetObject on the specific bucket ARN
  2. Store an IAM user's access key and secret key as environment variables and use them in the SDK
  3. Embed the access key directly in the function's deployment package
  4. Make the S3 bucket public so any caller, including the function, can read objects
Show the answer and explanation

Correct answer: A.

Option A is correct because execution roles provide temporary credentials scoped to exactly the permissions the function needs. Option B is incorrect because long-lived credentials in environment variables are harder to rotate and audit than a role. Option C is incorrect because hardcoded keys in code are a credential exposure risk and cannot be rotated without a redeploy. Option D is incorrect because this exposes the data to the entire internet, far beyond what the function needs. Lambda execution roles are the standard way to grant a function least-privilege, automatically rotated access to AWS services.

Sample question 3 Deployment

A team wants to deploy an updated Lambda function version to production while sending only 10% of traffic to it initially, and automatically roll back if CloudWatch alarms indicate errors, without writing custom traffic-shifting code. Which combination should the team use?

  1. Use an Application Load Balancer with weighted target groups pointing at two Lambda functions
  2. Create two separate API Gateway stages and have clients randomly choose one
  3. Deploy with AWS CodeDeploy using a Lambda canary deployment configuration, with a CloudWatch alarm attached for automatic rollback
  4. Publish a new Lambda version and manually update the alias weights every few minutes while watching CloudWatch dashboards
Show the answer and explanation

Correct answer: C.

Option A is incorrect because ALBs support weighted routing to Lambda targets, but this does not include CodeDeploy's automatic alarm-based rollback of the deployment itself. Option B is incorrect because this pushes traffic-splitting logic to the client and provides no automatic rollback based on alarms. Option C is correct because CodeDeploy's Lambda deployment types natively shift a percentage of traffic to the new version using aliases and roll back automatically if the configured alarm goes into ALARM state. Option D is incorrect because this requires manual, custom traffic shifting instead of an automated, alarm-driven capability. CodeDeploy integrates directly with Lambda aliases for canary and linear deployments with automatic, alarm-triggered rollback.

Sample question 4 Troubleshooting and Optimization

An application calls a downstream AWS service and occasionally receives ThrottlingException responses during traffic spikes. The team wants the application to handle these transient errors gracefully instead of failing the request immediately. What should the developer implement?

  1. Retry the request with exponential backoff and jitter
  2. Immediately retry the request in a tight loop until it succeeds
  3. Catch the exception and silently ignore the failed request
  4. Increase the Lambda function's timeout value
Show the answer and explanation

Correct answer: A.

Option A is correct because spacing out retries with increasing, randomized delays reduces the chance of repeated collisions with the throttling limit and gives the service time to recover. Option B is incorrect because rapid retries without backoff can worsen throttling by adding more load exactly when the service is already rejecting requests. Option C is incorrect because silently dropping the request loses data or work instead of handling the transient error. Option D is incorrect because a longer timeout does not address a service actively rejecting the call with a throttling error. Exponential backoff with jitter is the standard, AWS-recommended way to handle throttling and other transient errors.

Sample question 5 Development with AWS Services

A developer is reviewing how Lambda concurrency settings behave. Which TWO statements are correct? (Select TWO) (Choose 2.)

  1. Provisioned concurrency must be configured on a published version or an alias, not on $LATEST
  2. Reserved concurrency pre-initializes execution environments so that cold starts are removed
  3. Provisioned concurrency is billed only for the time that invocations are actually running
  4. Setting reserved concurrency to 0 lets the function scale up to the account limit
  5. Reserved concurrency guarantees a function a share of the account concurrency and also limits the function to that value
Show the answer and explanation

Correct answer: A and E.

Option A is correct because provisioned environments are pre-initialized for a specific published version, so the unpublished $LATEST version cannot be targeted. Option B is incorrect because reserved concurrency does not warm anything; it only allocates and caps capacity. Option C is incorrect because provisioned environments are charged for as long as they are configured, in addition to invocation charges. Option D is incorrect because a value of 0 throttles every invocation and is commonly used to stop a function. Option E is correct because the reserved amount is both dedicated to the function and its maximum, so it can protect other functions and downstream systems. Reserved concurrency is about capacity allocation and limits; provisioned concurrency is about pre-warmed environments.

Sample question 6 Security

An application's IAM role has a policy that allows dynamodb:Query on a table but the application also needs to prevent any single caller identity from reading items belonging to another tenant, where each item has a partition key equal to the tenant ID. Which approach enforces this at the IAM level without changing application code for every table?

  1. Create a separate IAM policy statement per tenant that lists the tenant's exact partition key value
  2. Rely on the application to filter Query results in code before returning them to the caller
  3. Enable point-in-time recovery on the table
  4. Use an IAM policy condition with dynamodb:LeadingKeys set to the tenant ID from a session tag, combined with temporary credentials obtained per tenant via AssumeRole
Show the answer and explanation

Correct answer: D.

Option A is incorrect because this does not scale as tenants are added and requires ongoing policy maintenance for every new tenant. Option B is incorrect because code-level filtering does not prevent the underlying Query from reading another tenant's data and is not an IAM-level control. Option C is incorrect because point-in-time recovery is a backup capability and has no effect on per-item access control. Option D is correct because the LeadingKeys condition restricts DynamoDB fine-grained access to items whose partition key matches an attribute of the caller's session, enforcing tenant isolation at the API level. Fine-grained access control with LeadingKeys lets one IAM policy generically restrict access to items by partition key using a session attribute.

Sample question 7 Deployment

A team manages three CloudFormation stacks: a networking stack that exports a VPC ID and subnet IDs, an application stack that imports those values with Fn::ImportValue, and a database stack that also imports the VPC ID. The team now needs to change the CIDR range of the VPC, which requires replacing the VPC resource in the networking stack. What blocks this update, and what must be done first?

  1. CloudFormation prevents deleting or replacing an exported value while other stacks still import it; the application and database stacks must stop importing that value, or be deleted, before the networking stack can be updated
  2. Only stacks in the same AWS account can import values, so this scenario is not possible
  3. The networking stack must be deleted and recreated because CIDR blocks can never be changed on an existing VPC resource
  4. CloudFormation will automatically update all stacks that import the value once the networking stack changes
Show the answer and explanation

Correct answer: A.

Option A is correct because exported values that are actively imported by other stacks are protected from changes that would remove or replace them, to avoid breaking the dependent stacks. Option B is incorrect because cross-stack references work within the same account and Region, which is consistent with the scenario as described, so this option misdiagnoses the situation. Option C is incorrect because recreating unrelated stacks is not required; the blocker is specifically the cross-stack export dependency, and CloudFormation would attempt replacement if the export were free. Option D is incorrect because cross-stack references are not automatically propagated; an update that would remove or replace an in-use export is blocked instead. Cross-stack exports that are still imported elsewhere block updates that would remove or replace the exported resource.

Sample question 8 Troubleshooting and Optimization

A serverless application's Lambda function reads a large reference dataset from S3 on every cold start, adding around 4 seconds to cold start latency. The dataset changes only once a day. The team wants to reduce this latency for cold starts without moving to a different compute service. Which optimization is most effective?

  1. Reduce the memory allocated to the function to lower cost
  2. Use Lambda SnapStart (for supported runtimes) or cache the dataset in /tmp with a check for freshness, loading it once per execution environment instead of downloading it on every cold start
  3. Increase the function's timeout to allow the download to complete
  4. Move the dataset download into the function handler so it happens on every invocation
Show the answer and explanation

Correct answer: B.

Option A is incorrect because lower memory generally reduces available CPU and network throughput, which would make the download slower, not faster. Option B is correct because SnapStart resumes from a pre-initialized, cached snapshot after initialization has already run once, and caching the dataset locally across warm invocations avoids repeating the download for the lifetime of that execution environment. Option C is incorrect because a longer timeout only allows the slow operation to finish; it does not make the operation faster or avoid repeating it. Option D is incorrect because moving initialization work into the handler makes even warm invocations pay the cost repeatedly, which is worse, not better. Cold start optimizations focus on doing expensive initialization once per execution environment (or using SnapStart) rather than on every invocation.
