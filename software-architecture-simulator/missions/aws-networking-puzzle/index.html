The AWS Networking Puzzle

Payments time out, the public endpoint is unreachable, and the security scan is red.

  • Design project
  • Intermediate
  • About 35 minutes
  • Free, in your browser

Play this mission

The scenario

A new environment was assembled in a hurry from console clicks. The checkout API sits in a private subnet and cannot call the payment provider. The public load balancer is not reachable from the internet. And an automated scan flagged exposed databases, open SSH, a public bucket and a wildcard IAM role. Make it work — and make it safe.

Context. Staging-to-production cutover for “PayLane” checkout in two days.

What is at stake. No payments can be processed and the security team has blocked go-live.

Your brief

  • All paths must flow: Internet → ALB → API → database / payment provider / storage.
  • No critical or high security findings.
  • Budget $450 / month (simulated estimate).
  • Use the Network inspector to understand each failure — do not guess.

What you will learn

  • VPCs, subnets and route tables
  • Public vs private subnets, internet and NAT gateways
  • Security groups (stateful) vs NACLs (stateless)
  • Least-privilege IAM
  • Reading a reachability analysis layer by layer

Builds: Cloud networking, AWS services, Solution architecture.

How it plays

You are given a running architecture and the evidence a real engineer would have: metrics, logs, traces, cost and recent changes. Form a hypothesis, make a change, deploy it, and read why the system reacted as it did. A verification load test then scores your design and a debrief explains the root cause and the alternatives. Nothing here touches a real cloud account.
