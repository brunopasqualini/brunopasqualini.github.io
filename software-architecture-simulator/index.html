Software architecture and system design simulator

Learn system design by running it. Take over a live cloud architecture in a browser, find out why it is failing from metrics, logs and traces, redesign it, deploy the change and see what each decision costs. Fourteen missions, no signup, nothing to install.

Start the first incident

How a mission works

  1. Investigate. Open metrics, logs, traces, dependencies, cost and security panels to gather evidence.
  2. Form a hypothesis. Say what you think the root cause is. Diagnosis quality is scored.
  3. Design a change. Drag components onto the canvas, connect them and configure them. Edits are a draft.
  4. Deploy and read the consequences. The simulator explains what changed and why, for example that scaling the app tier raised database connections past the limit.
  5. Verify and debrief. A verification load test scores ten dimensions and gives a structured debrief, with an architecture decision record and a postmortem.

What you will practise

  • Capacity analysis, bottlenecks, indexes, connection pooling and caching trade-offs
  • Timeouts, retries, circuit breakers, queues, dead-letter queues and idempotency
  • Availability zones versus Regions, RTO and RPO, and disaster recovery strategies
  • VPC networking, IAM least privilege and security groups, with a network inspector
  • Cost trade-offs: right-sizing, data transfer, logging and cost against reliability
  • Rate limiting, backpressure, hot keys and replication lag

The missions

Fourteen missions in five levels, from fixing one slow endpoint to designing a platform from a blank page. Each page below describes the scenario and what it teaches; the simulator itself runs the mission.

Level 1: Software Engineer

Fix bugs, design APIs, improve code structure, and understand how applications behave.

  • Incident · Intermediate · ~25 min

    The Database Meltdown

    Flash-sale traffic is 3× normal and checkout is timing out.

  • Design project · Beginner · ~15 min

    The N+1 Endpoint

    One product page, a dozen database round trips, and a database that cannot keep up.

  • Design project · Beginner · ~15 min

    The Impatient Client

    A timeout that is shorter than the real answer time, and a client that never gives up.

Level 2: System Designer

Design databases, caches, queues, service boundaries, and architectures that handle growth.

  • Design project · Beginner · ~20 min

    The Growing Monolith

    Five domains, one deployable, three squads stepping on each other.

  • Incident · Advanced · ~35 min

    The Queue That Never Drains

    Fulfilment events pile up, some messages fail forever, and the ledger database spikes.

  • Incident · Intermediate · ~25 min

    The Stale Receipt

    Customers pay, land on their confirmation page and read “Order not found”.

Level 3: Cloud Engineer

Build networks, configure AWS services, manage permissions, and design for availability, security and cost.

  • Design project · Intermediate · ~35 min

    The AWS Networking Puzzle

    Payments time out, the public endpoint is unreachable, and the security scan is red.

  • Design project · Advanced · ~40 min

    The Cloud Bill Shock

    The invoice tripled; customers did not.

  • Incident · Intermediate · ~25 min

    The Hot Key

    The table has spare capacity and it is still throttling.

Level 4: Platform Engineer / SRE

Automate delivery, build reusable platforms, improve observability, and engineer resilience.

  • Incident · Intermediate · ~30 min

    The Unreliable Deployment

    A fresh release is throwing intermittent errors in production.

  • Incident · Intermediate · ~25 min

    The Noisy Neighbour

    One partner’s runaway sync job is using everyone’s capacity.

  • Design project · Advanced · ~30 min

    The Regional Outage

    The board asks one question: if our Region disappeared, how long until we are back and what do we lose?

Level 5: Principal Engineer / Architect

Decide across whole systems, balance competing requirements, manage organisational complexity, design for failure at scale.

  • Design project · Advanced · ~40 min

    The Blank Page

    Design a ticketing platform from nothing, against requirements that pull in different directions.

  • Design project · Advanced · ~45 min

    The Merger

    Two platforms, six squads, one audit, and a peak that is three times bigger than last year.

Frequently asked questions

What is the software architecture simulator?

Engineering Ops is a hands-on simulator for system design and site reliability. You get a running cloud architecture, investigate an incident from metrics, logs and traces, change the design, deploy it and watch how the system reacts.

Is it free, and do I need an AWS account?

It is free and needs no account, no install and no cloud access. Everything is simulated in your browser, and costs are estimates, not AWS prices.

Is it a real cloud?

No. It is a deterministic, rule-based simulation that models how load, failures, queues, caches and databases behave, so you can practise decisions safely and see the consequences.

Who is it for?

Software engineers moving into system design, cloud and DevOps engineers who want practice beyond tutorials, and people preparing for architecture interviews or AWS certifications who want to make and defend design decisions.

Is my progress saved?

Yes, in your browser (localStorage). You can export it from Settings and import it elsewhere.
